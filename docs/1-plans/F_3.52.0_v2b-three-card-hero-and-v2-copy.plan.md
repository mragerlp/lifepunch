## Solution Architecture

All changes are surgical edits to the five flat HTML files in `.tmp-cvlbrand\` (each
page carries inline CSS/JS), plus two new static assets. No build system exists — edits
are per-page and must be kept consistent by the shared sensor script at the end.

**V2B hero (home only):** keep orb, veins, orbit canvas, and entrance animations
untouched (owner-locked). The four `arch-node` anchor chips are replaced by three
`<button>` seats on the orbit ring: **C → top-left, V → top-right, L → bottom-center**
(reusing the existing orbit-radius CSS vars). **Three-key data model, applied
everywhere:** every four-key structure in the hero canvas JS becomes three-key —
`CORNER_TO_PILLAR` → `SEAT_TO_CARD` (`tl:c, tr:v, bc:l`), the orbit angle map
(`workflows/knowledge/governance/outcomes` angles → `c/v/l` at NW/NE/S), keepout boxes
(computed from live DOM rects, so they follow the three buttons automatically — verify),
entrance-delay CSS rules (`.arch-node.tl/.tr/.bl/.br` → three seat classes), and vein
linkage targets. No four-key structure may survive with a dangling key. Each button
opens its card (one open at a time, toggle + switch, Esc closes, backdrop click closes).
**Card placement:** cards render as a sibling of `.arch-map`, never inside it —
mobile `.arch-map` has `overflow: hidden` (index.html ~2435) and would clip them.
Desktop: absolutely positioned panel adjacent to the orb (anchored to the hero grid
cell, outside `.arch-map`). Mobile: full-width block under the hero. Verbatim
≤4-sentence copy + link per card. Letter hover = brighten linkage, per existing visual
grammar. Pillar deep-links move to a new mono text row under the hero copy:
`Workflows · Knowledge · Governance · Outcomes` → `/system/` lane anchors.

**V2 copy:** verbatim insertions per the brief; company references read Cavelux, method
references stay CVL / Collaborative Value Loop; "black hole" spent max twice per page.

**404:** Cloudflare Pages serves a root `404.html` with real 404 status when present —
this alone ends the SPA-style landing fallback. Page is minimal on-brand: voxel orb
mark, "Nothing here. The loop holds.", home link, tokens-only, radius 0, noindex.

**og:image:** copy the CAVELUX card into `/social/`, then swap `og:image` +
`twitter:image` URLs on all five pages (dimensions stay 1200×630).

## Technical Considerations

- **Pattern usage**: flat-HTML per-page edits; keep the five pages' shared chrome
  byte-consistent where they overlap (footer, nav, meta shape). Sensor script enforces.
- **CVL authority**: deploy to production is part of the ruled manifest (site lane =
  wrangler deploy, not git; no commit in this slice). Any git landing of the plan doc
  follows normal Bloodwave gates.
- **IP fence**: cards and copy say "custom-built / molded to your operation" — never
  "you get our framework". Review gate greps for framework-transfer phrasing.
- **Sensor Law**: every acceptance claim below has a named sensor (curl grep counts,
  Playwright interactions, pixel-sample lime measure, HTTP status codes).
- **Edge cases**: 404.html must not break the `_middleware.js` 301 host redirect
  (middleware runs first, `context.next()` unaffected); reduced-motion global CSS
  kill-switch already exists per page — card open must be state-toggle, not
  animation-dependent, so it works with `animation: none`.
- **Risk**: hero JS is the largest inline script on the site (orbit/vein/linkage
  system). Chip retirement must not orphan references (`CORNER_TO_PILLAR`, keepouts,
  entrance delays on `.arch-node.*`). Mitigation: node --check + Playwright console
  error sensor + screenshot diff of the resting hero (must look unchanged except seats).
