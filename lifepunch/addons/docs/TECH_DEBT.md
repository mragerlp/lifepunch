## Future feature ideas (staff menu)
- **EVIP "fallback staff" — commands usable only when no staff are online.** LifePunch wants
  `EVIP` to act with (a subset of) staff powers *only while zero staff are connected*, so the
  community is never left fully unmoderated. The staff menu already computes the exact signal
  this needs: `staffCount` (`StaffTierGroups().Sum(g => g.Players.Count)`), where **"no staff
  present" == `staffCount == 0`** — the same number the collapsed rail's shield badge shows.
  - **Authority (required):** the real gate must be **host-side / server-authoritative** — a
    `[Rpc.Host]` that re-checks `online staff == 0` at command time before dispatching. The HUD
    may only *reflect* eligibility; a client must never be trusted to self-certify "no staff on."
  - **UI affordance:** for an EVIP caller, surface their allowed actions as **enabled only while
    `staffCount == 0`**, with a tooltip like *"Available because no staff are online,"* and grey
    them out the instant any staff member connects.
  - **Classification:** EVIP counts as **non-staff** for this check (they're the fallback, not
    staff) — which the current roster split already enforces (`GroupName == NonStaffGroup`).
  - **Scope TBD:** which subset of commands EVIP gets, and whether it's a fixed list or a new
    permission grant the portal owns.
