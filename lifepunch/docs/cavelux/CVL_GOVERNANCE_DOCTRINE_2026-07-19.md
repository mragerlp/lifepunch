# CVL GOVERNANCE DOCTRINE — the law the armor is built against (2026-07-19)

Owner-authored, ratified this session. This is the doctrine that makes the CVL MCP ("universal armor") safe to expand. Every MCP tool is built against this. This is the point CVL stops being "a collection of AI tools" and becomes a GOVERNED SOFTWARE OPERATING SYSTEM.

## THE CORE LAW (non-negotiable, the sentence the whole armor hangs on)
**MCP EXPANDS CAPABILITY. IT DOES NOT EXPAND AUTHORITY.**

## THE FOUR ENFORCEMENT CLAUSES (owner-ratified — the teeth)
1. **DEFAULT DENY** — a new MCP tool receives NO write authority until explicitly classified and approved. Tools are born powerless and EARN authority by explicit classification; never born capable and fenced later.
2. **LEAST PRIVILEGE** — each agent sees only the tools and operations required for its assigned seat and task. (This is also the 672-tool-cap cure: seat-scoped tool exposure.)
3. **EVIDENCE BEFORE ACCEPTANCE** — every material tool action must return machine-verifiable evidence: diff, log, status, screenshot, test output, or runtime sensor result. No evidence = not accepted.
4. **HUMAN-CONTROLLED CANON** — no model may independently merge, deploy, publish, alter governing canon, or make final product decisions.

## THE COMPLETE CVL OPERATING PRINCIPLE (owner verbatim)
Agents may inspect broadly.
Agents may act within assigned scope.
Agents must refuse unauthorized operations.
Agents must return evidence for material claims.
MCP grants access to capability — not ownership of decisions.
Bloodwave retains authorization, acceptance, merge, deployment, and canon authority.

## WHAT SEPARATES CVL FROM ORDINARY "AI AUTOMATION"
Typical agent stack: Model + tools + broad permissions.
Collaborative Value Loop: Specialized agents + governed tools + explicit authority ceilings + independent review + machine-verifiable evidence + human-controlled canon.

## THE TOOL CONTRACT (every MCP tool MUST specify — the feature-canon schema)
1. **Named owner** — who owns this tool.
2. **Read/write classification** — read-only, or write (write triggers stricter rules).
3. **Explicit permission ceiling** — the maximum it may do; it cannot exceed this.
4. **Evidence returned after action** — machine-verifiable proof of what it did (Sensor Law, mandatory).
5. **Failure behavior** — what it does when it can't act: REFUSE + report, never guess/improvise.
6. **Bloodwave gate** — required for any destructive or canonical operation (merge, deploy, delete, economy write, brand/doctrine change).
