  canon decisions, hard bug reasoning) → **Sonnet** (usage/budget fallback:
  summarization, cheap docs, lower-risk briefs)

**Claude Code (implementation layer) — primary model: Opus**
- Primary IDE for all future LIFEPUNCH work
- Reads the repo, edits files, runs tests, drives s&box editor work
- Syncs to the editor tree via `lifepunch/scripts/Sync-LifePunchAddonsToDxrp.ps1`
  (`-WhatIf` first, every time; the dry run is the authorization — if it shows only
  files changed this session, run it for real; anything else, STOP and report)
- Gates with the Sensor Law: every claim carries its sensor; FRESH assertions require
  the compile log to postdate the write plus a positive code-string ID proving the
  compiler/parser read the new bytes; when no sensor reads the thing under test,
  build one
- Reports changed files + proof; commits only after a passing gate and Bloodwave GO

**Codex (review layer)**
- Reviews the DIFF, post-build, pre-merge
- Verdicts: PASS / REVISE / HOLD — on scope match, proof quality, and lane discipline
- Codex reviews diffs, never re-litigates rulings. A HOLD means "the build does not
  match the ruling," not "I disagree with the ruling." Ruling disputes go to Bloodwave.
- Codex REPLACES Grok/Cursor in the standard loop. Grok/Cursor is retired to
  optional outside second opinion, invoked only when Bloodwave asks; it does not
  originate deliverables and is not in the standard review path.

**Cornerman (Green — Tier-3 local worker)**

- Green fast-fail law stands: no retries, no detach, no polling loops, no CIM/WMI,

**Bloodwave**

### Transport Law (codified)

```
Long pasted handoffs between Claude Chat and Claude Code are a known hazard
(empty-response bug). Do not rely on them.

PASTE for state changes:   relays that fit on roughly one screen
                           (CVL RELAY format — rulings, GOs, verdicts)
FILE for briefs:           anything longer, or anything an agent must re-read
                           later, goes to a repo-tracked handoff file
```

**Handoff file pattern:**
1. Claude Chat authors the brief and produces it as a downloadable file
   (Chat cannot write to Red's disk — the file travels as a download/attachment,
   which is the proven-reliable transport)
2. Bloodwave saves it to `lifepunch/docs/handoff/CLAUDE_CODE_BRIEF_<TASK>_<DATE>.md`
3. Claude Code receives only a short paste:

```
Read this handoff and execute only the approved scope:
lifepunch/docs/handoff/CLAUDE_CODE_BRIEF_<TASK>_<DATE>.md

Before editing, report:
1. branch
2. HEAD
3. clean/dirty state
4. intended files
5. forbidden files
6. wait for Bloodwave GO
```

Handoff files are WRITE-ONCE. The repo gains a durable record of what every agent
was told. Screenshots remain valid transport (they always worked); attachments
into Chat are read from disk even when previews render blank.
