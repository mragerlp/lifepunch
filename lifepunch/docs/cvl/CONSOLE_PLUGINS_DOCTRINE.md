## 0. The one law that governs all of it

PLUGINS ARE CAPABILITY, NOT AUTHORITY. No plugin grants a seat any
permission beyond its CVL charter. A proposal-only seat with a commit
plugin installed is still proposal-only. A two-key action reached
through a plugin affordance is still two-key. When a plugin's default
behavior conflicts with CVL law, CVL law wins and the plugin feature
goes unused. Installed is not invoked.

## 2. Classification and rules per plugin

### CLASS A — Advisory/capability enhancers (use freely, Sensor Law applies)
- typescript-lsp, pyright-lsp: static diagnostics. NOTE: the LIFEPUNCH
  tree is C#/.razor/SCSS — these fire on tooling scripts only. An LSP
  diagnostic is a STATIC sensor; it never substitutes for compile or
  runtime proof.
- context7: live library docs lookup. Citations from it name the
  source. Never outranks the s&box/DXRP truth in-tree; engine-truth
  skills and machine-verified reads win on conflict.
- security-guidance: advisory during money-path and permission work.
  Its flags are leads-grade; route real findings into the normal
  defect/ruling flow, not silent self-repair.
- explanatory-output-style, code-simplifier, frontend-design,
  feature-dev, superpowers: workflow/skill enhancers. frontend-design
  guidance yields to LIFEPUNCH_UI_STANDARD and Law 17 wherever they
  conflict — LIFEPUNCH visual canon outranks generic design advice.
- claude-code-setup: environment bootstrap only; never modifies the
  canonical tree.

### CLASS B — Review toolchain (complements the loop, replaces no seat)
- code-review, pr-review-toolkit: Red may self-review pre-commit and
  SHOULD before every PR — this raises floor quality. It does NOT
  replace Codex's review seat in the CVL loop or Fable's gate review.
  Plugin review output is a sensor input to the existing gates, never
  a gate verdict itself.
- commit-commands: convenience wrapper. Commit DISCIPLINE is
  unchanged: commits only after proof gates, attribution-clean, no AI
  trailers, on the correct branch. If the plugin's commit template
  injects trailers or co-author lines, strip them — attribution
  cleanliness is a standing law and this plugin is the likeliest
  place it silently breaks.

### CLASS C — Automation with standing effects (Bloodwave GO required)
- hookify: hooks are STANDING RULES (persistent config class). No
  hook is created, modified, or removed without explicit Bloodwave GO
  naming the hook. Hooks live seat-local (settings.local.json class /
  untracked), never in tracked settings. Any hook that auto-triggers
  commits, pushes, syncs, or network calls is forbidden outright.
- ralph-loop: autonomous looping is ULTRACODE-CLASS. Bloodwave
  console invocation only, with a scoped task and a stated stop
  condition. NEVER during chair/observed phases, never on the
  canonical tree without a scoped GO, never self-invoked by a seat.
  Loop output lands as a normal seat report and gets graded — the
  loop does not self-certify.

### CLASS D — Browser automation (surface-scoped)
- chrome-devtools-mcp, playwright: permitted on LOCAL and dev
  surfaces (localhost, local UI testing, editor-adjacent pages).
  FORBIDDEN on credentialed surfaces — dxrp.net portal, GitHub web,
  any logged-in session — without explicit Bloodwave GO per session.
  Credentials are NEVER entered by any plugin browser under any
  instruction. Portal work remains the ratified portal lane.
  Playwright evidence (screenshots/traces) counts as eyes-class
  sensors for local UI only.

### CLASS E — Canon-surface writers (proposal-only path mandatory)
- claude-md-management: CLAUDE.md is RATIFIED CANON. This plugin may
  DRAFT and PROPOSE CLAUDE.md changes; it never auto-applies them.
  Every CLAUDE.md change rides a PR through the normal gate review.
  Auto-maintenance features stay off.
- skill-creator: seat-local skill creation (.agents/skills, untracked)
  is free. PROMOTING a skill to the tracked tree is a canon act — PR
  + gate review. Skills must not encode instructions that conflict
  with CVL law; a skill is subordinate to this doctrine.

### CLASS F — Dormant (no LIFEPUNCH lane)
- vercel: no deployment target exists in this project. Unused until a
  ruling creates a lane (e.g., lifepunch.co work). Do not connect it
  to any account meanwhile.

## 3. Cross-cutting rules

1. SENSOR LAW EXTENSION: every plugin output is a claim carrying its
   sensor ("per code-review plugin", "per pyright"). Plugin claims
   about runtime behavior are inference until runtime-proven.
2. TWO-KEY UNTOUCHED: merge, ship/publish, canon ratification,
   destructive ops, DXRP sync, real money — no plugin affordance
   reaches these without Bloodwave's word. A plugin that offers a
   one-click path to any of them gets the click withheld.
3. NETWORK DISCIPLINE: plugins that call out (context7, browser
   plugins, vercel) send no repo secrets, no portal data, no
   credentials outbound. Key Law applies to plugin-held auth: own
   minimum-scope keys, never shared, never transcribed into chat.
4. EDITOR ACCESS LAW UNCHANGED: no plugin gives Codex mutation
   authority or a second seat DRIVE. Browser plugins are not the
   editor bridge; the bridge remains the ratified editor lane.
5. GREEN CONSOLE PARITY: when CORNERMAN runs a Claude console, this
   doctrine applies verbatim. Green's charter (static-only audit,
   OUTBOX-only writes, ADVICE headers) is not expanded by any plugin.
6. FAILURE HONESTY: a plugin misfire, hallucinated citation, or
   unexpected side effect is REPORTED in the seat's record, not
   silently retried into oblivion. Plugin defects get filed like any
   other defect.
7. BOOT ADDENDUM: seat boot checklists gain one line at next boot-file
   touch — "Confirm installed plugins conform to
   CONSOLE_PLUGINS_DOCTRINE; report any plugin not classified there."
   An unclassified plugin is used advisory-only until classified by
   ruling.

## 4. Why this exists

The consoles are the muscle of the CVL — these plugins make Red
faster at review, cleaner at commits, and give both consoles better
static eyes. The doctrine exists so the muscle never outruns the
skeleton: every catch this stack made (inverted root cause, EOL
falsification, compiled-artifact staleness, self-pull decoy) came
from DISCIPLINE, not capability. Plugins add capability. The
discipline stays exactly where it is.
