### Why the store page works (and the home page didn't)
The home/server-list capture was rejected as "not proper for the goods/services" and "does not
demonstrate use of mark in commerce." The **store page cures the commerce defect**:
- Shows the **LIFEPUNCH** mark (LP logo + wordmark) as the source/provider.
- Shows the mark **used in commerce** — paid packages **VIP $10 / EVIP $25** ("help keep our servers
  running") — a direct, paid mark↔service association.
- Perks (Builder status, prop limits, queue skip, minigame starts, exclusive jobs) all reference the
  **LIFEPUNCH online game servers** → the Class 041 "providing online video games" service.
- **DXRP is nominative only** ("Minigame Starts (DXRP WIP)", "Exclusive Jobs (DXRP WIP)").
- Real, live website (lifepunch.co/store).

### Make the FINAL specimen bulletproof
1. Capture with the **browser URL bar (`lifepunch.co/store`) and date visible** so it reads as a live
   page, not a digital mockup (USPTO rejects mockups).
2. Frame so the **LIFEPUNCH header + the priced packages (VIP/EVIP)** are visible together (mark +
   commerce in one image).
3. Specimen description to enter on TE: *"Live screenshot of the LIFEPUNCH website store
   (lifepunch.co/store) showing the LIFEPUNCH mark offering paid membership packages (VIP, EVIP)
   granting access and perks on LIFEPUNCH's online video-game servers."* Set "webpage screenshot = Yes".
4. Optional/stronger: also pair with the server-browser/home capture (mark + joinable servers) so the
   service-being-rendered is shown too; let TE's attorney pick the strongest.
